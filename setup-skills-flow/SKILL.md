# 初始化 Agent 工作环境

在目标仓库建立一个可导航的持久文档区和一个供 agent 使用的本地工作区。先读取仓库事实，再生成内容；目录名只是默认值，不应与项目已有约定形成两套并行结构。

## 1. 确认目标与现状

确定目标仓库根目录。检查根目录和相关子目录中的 `AGENTS.md`、`CLAUDE.md`、`docs/`、`.agent/`、`.gitignore`、项目说明、构建配置与现有文档入口。确认当前工作树状态，识别用户已有修改。若用户指定了目录结构或工作区用途，采用用户的约定。

在创建或修改任何文件前，根据当前 Agent 的宿主约定、已加载的指令和工具文档确定默认读取的根目录指令文件。当前环境明确使用 `AGENTS.md` 时，以它为主；明确使用 `CLAUDE.md` 时，以它为主。不要把主文件名交给用户选择，也不要仅根据两个文件是否存在来猜测。

后文的“主指令文件”均指当前 Agent 环境确定的文件。若环境无法确认主文件，先继续检查可用的宿主约定；仍无法判断时停止写入并报告原因，不用用户选择替代环境事实。若 `AGENTS.md` 和 `CLAUDE.md` 都存在，检查它们的作用域和冲突，以主指令文件为当前修改对象，保留另一文件原有内容。

从仓库实际文件提取项目用途、关键目录、常用开发命令和文档分类。无法验证的命令或架构信息留空，不写成事实。已有文档有稳定位置时，沿用该位置，并在索引中指向它。

## 2. 建立 `docs/`

新仓库或没有文档约定的仓库使用下列基线。每个目录放一份简短 `README.md`，说明收纳什么内容并链接已有文档；没有实际内容时只写用途，不生成虚构的 PRD、spec、ADR 或研究结论。

```text
docs/
  README.md                # 文档总索引与阅读顺序
  proposals/README.md      # 待评估的产品或技术提案
  prd/README.md            # 已明确的产品需求与 PRD
  specs/README.md          # 技术行为契约与验收约束
  architecture/README.md   # 系统、模块与实现设计
  decisions/README.md      # 已作出的决策及其理由（ADR）
  research/README.md       # 可追溯的调研记录
```

`docs/README.md` 是入口：列出实际存在的分类、每类文档的用途和链接。对于已有仓库，只补缺失的入口或分类；若项目已用其他名称（例如 `docs/design/` 或 `docs/adr/`），在索引中沿用，不另建同义目录。调整旧路径前先检查引用和用户约定。

## 3. 编写根目录主指令文件

把它写成 agent 的简短导航和仓库工作约定，内容依据实际证据，建议包含：

- 项目是什么，主要代码和文档入口在哪里。
- 开始任务时应读取哪些项目文档；通过 `docs/README.md` 到达细节。
- 已验证的构建、测试、检查命令及其适用范围；没有证据时省略。
- 已有的代码与文档约定，以及如何使用 `.agent/`。

保留主指令文件的有效指令和作用域，不用通用模板覆盖项目规则。对于已有内容，只做必要的补充、纠错和去重。把长期事实放在 `docs/`，让主指令文件保持为简洁的入口；临时任务状态放在 `.agent/`。子目录已有 `AGENTS.md` 或 `CLAUDE.md` 时保留其局部约定。

如果另一种根目录指令文件不存在，在主指令文件和文档入口整理完成后，向用户说明可选的兼容链接，并询问是否创建。例如当前主文件是 `AGENTS.md` 时，询问是否创建指向它的 `CLAUDE.md`；当前主文件是 `CLAUDE.md` 时反向处理。只有用户同意后才创建链接；创建后验证链接目标和版本控制状态。若另一文件已存在，不自动替换为链接。

## 4. 建立 `.agent/` 工作空间

默认创建以下本地工作区：

```text
.agent/
  README.md          # 工作区用途和内容边界
  workspace/
    plans/           # 当前任务的执行计划
    notes/           # 调查笔记与临时记录
    handoffs/        # 跨会话或交接时的任务状态
```

`README.md` 说明 `.agent/workspace/` 用于进行中的工作，经过确认且需要长期保留的结论应整理进 `docs/`。在 Git 仓库中，若项目没有相反约定，在 `.agent/.gitignore` 中忽略 `/workspace/`，使工作区说明可跟踪、临时内容保持本地。若已有 `.agent/plans/`、`.agent/notes/` 或 `.agent/handoffs/`，先检查引用与内容；能够无冲突迁移时移入 `workspace/`，否则保留原内容并报告待处理的路径。不要清空或覆盖正在使用的笔记。用户希望共享计划或交接记录时，遵循其版本管理约定。

## 5. 验证与交付

检查 `docs/README.md`、根目录主指令文件与 `.agent/README.md` 三处入口均存在且链接指向真实路径；主指令文件的名称与当前 Agent 环境一致，其中的项目事实和命令有仓库依据；若用户同意创建兼容链接，验证链接目标正确；原有文档、规则与工作区内容仍在；重复运行不会产生同义目录或重复段落。查看最终 diff，报告主指令文件、兼容链接（如有）、新增或更新的路径、沿用的现有约定，以及仍需项目负责人补充的真实信息。仅生成工作环境，不把占位文档描述为已完成的设计或决策。
